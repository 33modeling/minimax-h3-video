01H100 4장 · 구성과 사전 점검GPU 메모리·CPU 메모리·드라이버·디스크부터

이 설명서는 기존 minimax-h3-video 저장소의 로컬 H100 4장 운용을 기준으로 합니다. 모델 파일, H3 생성 서버, 웹·CLI는 각각 역할이 다릅니다. 클라우드 API를 쓰려면 마지막 항목으로 이동하세요.

구성이 저장소에서의 역할
H100 4장 · GPU 0,1,2,3FL2VA 한 서버: 조건 인코더·VAE 1장 + 영상 모델 분산 3장. 같은 영상의 생성을 함께 처리합니다.
Diffusers에서 FL2VA + Ref2VA 동시 운용4장을 2장씩 분리합니다. 4장 전체를 한 서버에 쓰는 구성과 처리 특성이 다릅니다.
CPU 메모리현재 시작 스크립트는 Diffusers 서버 하나당 약 140GB의 적재 여유를 검사합니다. 두 서버면 약 280GB이며 컨테이너 한도도 따로 확인합니다.
드라이버·엔진기본 엔진은 Diffusers입니다. 드라이버 CUDA 버전으로 엔진을 자동 변경하지 않습니다. SGLang은 --engine sglang을 직접 지정할 때만 선택합니다.
nvidia-smi --query-gpu=index,name,memory.total,memory.used --format=csv
nvidia-smi topo -m
free -h
df -h /user-volume /group-volume /rdata
python3.12 --version
ffmpeg -version
ffprobe -version

df에는 실제 존재하는 저장 경로를 넣으세요. H100이라는 이름만으로 80GB 구성을 가정하지 말고 표시된 장당 메모리를 확인합니다. 컨테이너라면 /sys/fs/cgroup/memory.max와 memory.current도 확인하세요. GPU 4장의 총 메모리가 충분해도 특정 GPU나 CPU 적재 단계에서 OOM이 날 수 있습니다.

02코드 준비·경로 설정새 노드 설치와 기존 설치를 구분

인터넷이 되는 개발 PC에서는 저장소를 받습니다. 이미 코드가 있으면 새 복제본을 만들 필요가 없습니다. GitHub에 접속하지 못하는 클러스터에는 저장소의 동기화 스크립트로 코드를 전달합니다.

git clone https://github.com/33modeling/minimax-h3-video.git
cd minimax-h3-video

# 개발 PC → 클러스터. USER@HOST와 대상 경로를 실제 값으로 바꿉니다.
CLUSTER_SSH=USER@HOST CLUSTER_CODE_DIR=/user-volume/minimax-h3-video bash scripts/sync_to_cluster.sh

동기화 스크립트는 코드 대상 폴더에 rsync --delete를 사용합니다. 결과·모델·가상환경을 코드 폴더와 분리하고 대상 경로를 먼저 확인하세요. 다음 단계는 H100이 배정된 노드에서 진행합니다.

cd /user-volume/minimax-h3-video
# 기존 설정 파일이 있으면 덮어쓰지 말고 필요한 항목만 고칩니다.
editor .cluster_env.local.sh
# .cluster_env.local.sh 예시 — 설치된 실제 경로로 바꿉니다.
export GROUP_VOLUME_ROOT=/group-volume
export STORAGE_ROOT=/group-volume/YOUR_ACCOUNT/minimax-h3-video
export MODELS_DIR=/rdata/models
export H3_MODEL_DIR=/group-volume/models/MiniMax-H3
# 공유 Diffusers 변환본이 이미 있으면 그 위치를 지정합니다.
export H3_DIFFUSERS_DIR=/rdata/models/MiniMax-H3-diffusers

모델 기본 검색은 MODELS_DIR/MiniMax-H3부터 시작해 저장된 경로·공유 폴더를 확인합니다. 예시 경로가 실제 위치와 다르면 지정한 폴더를 사용하세요. 기존 변환본이 없다면 쓰기 가능한 H3_DIFFUSERS_DIR을 정합니다. 이 설정 파일은 Git에 올리지 않습니다.

03설치 · 가상환경·패키지·모델provision.sh와 고정 버전 사용

기본 도구가 없는 Ubuntu 24.04 노드에서는 관리 권한이 있는 사용자가 다음 시스템 패키지를 먼저 준비합니다. Ubuntu 22.04는 기본 Python이 다르므로 프로젝트에서 제공한 Python 3.12 이미지·인터프리터를 사용하세요. NVIDIA 드라이버와 CUDA 툴킷을 이 명령으로 교체하지 않습니다.

# Ubuntu 24.04 기본 패키지 예시 · 운영자가 필요한 경우에만 실행
sudo -A apt-get update
sudo -A apt-get install git curl ca-certificates rsync ffmpeg tmux python3.12 python3.12-venv python3.12-dev build-essential pkg-config

먼저 저장 공간과 모델 접근 권한을 확보합니다. 공식 모델의 이용 조건·접근 승인이 필요한 계정은 Hugging Face 모델 페이지에서 처리하세요. 기존 가중치가 있으면 재사용합니다.

# H100 노드의 코드 폴더에서
bash scripts/provision.sh

# 참고 이미지·영상·소리 모델까지 쓸 때는 위 명령 대신
bash scripts/provision.sh --ref

Diffusers 경로는 프로젝트의 constraints/h100-cu126-diffusers.txt를 사용합니다. 임의로 패키지를 최신판으로 모두 올리지 마세요.

구성고정 버전
PyTorch / torchvision / torchaudio2.7.1+cu126 / 0.22.1+cu126 / 2.7.1+cu126
diffusers / transformers0.41.0 / 5.14.1
accelerate / huggingface-hub1.14.0 / 1.33.0
Python 부트스트랩엔진 설치는 Python 3.12. CLI 패키지 자체는 Python 3.10 이상

Diffusers 설치는 CLI와 엔진 패키지를 가상환경에 설치하고, 공식 프롬프트 가이드를 받으며, 이미 준비된 구성 요소는 건너뜁니다. 기존 원본 텍스트 인코더를 재사용할 수 있을 때 추가 변환 파일은 FL2VA 약 72GB, Ref2VA 추가 약 62GB로 안내됩니다. 원본·변환본·캐시를 모두 새로 받는 총용량은 이보다 큽니다. 실제 여유 공간을 확인하세요.

# 모델은 건너뛰고 패키지·가이드만 다시 설치할 때
bash scripts/provision.sh --skip-model

# SGLang 경로에서 원본 가중치까지 새로 받아야 할 때만
bash scripts/provision.sh --engine sglang --download

# 새 터미널에서 설치된 환경을 불러옵니다.
source scripts/cluster_env.sh
python -m pip show h3video torch diffusers transformers
h3video --help

provision.sh 자체가 환경을 읽으므로 설치 전 수동 source는 필수가 아닙니다. 설치 후 CLI를 사용할 터미널마다 환경을 읽으세요. Hub 다운로드 실패 시 스크립트는 미러를 재시도합니다. 재실행하면 존재하는 모델 구성 요소를 확인하고 빠진 부분을 처리합니다. 설치 로그는 저장 루트의 logs/provision-*.log에 남습니다.

공식 참고: 모델·이용 조건 ↗ · Diffusers H3 워크플로 ↗

SGLang을 선택할 때만 아래 명령을 사용합니다. 기본 Diffusers 가상환경(.venv-diffusers)과 SGLang 가상환경(.venv)은 분리됩니다.

bash scripts/provision.sh --engine sglang
bash scripts/up.sh --engine sglang
# 별도 터미널에서 웹 UI를 쓸 때
bash scripts/web.sh --engine sglang
04H100 4장 배치·생성 서버 시작FL2VA 4장 또는 두 서버에 2장씩

먼저 실제 배정된 GPU 번호와 다른 작업의 사용 여부를 확인합니다. 아래 시작 명령은 운영자가 실행할 때의 절차입니다. up.sh는 기존 H3 생성 서버 묶음을 정리하고 시작하므로, 실행 중인 H3 작업을 확인한 뒤 사용하세요. 웹 UI는 별도입니다.

# 점검만: 생성 서버를 시작하지 않습니다.
bash scripts/up.sh --check

# 터미널 A · FL2VA에 H100 4장 전체 배정
bash scripts/up.sh --gpus 0,1,2,3

위 구성은 글·첫 프레임·끝 프레임 생성용입니다. ✓ fl2va 준비됨이 나올 때까지 기다립니다. 원본 서버 로그가 이 터미널과 파일에 남습니다. 단순히 HTTP 포트가 응답한다고 모델 준비가 끝난 것은 아닙니다.

# Diffusers에서 FL2VA + Ref2VA를 동시에 사용할 구성
# 위 4장 단일 서버 구성 대신 선택합니다.
bash scripts/up.sh --ref --gpus 0,1 --ref-gpus 2,3

두 GPU 집합은 겹치면 안 됩니다. SGLang 경로의 자동 배정은 서버당 4장이므로 H100 4장으로 두 서버를 동시에 띄우는 계획과 혼동하지 마세요. 해당 엔진에서 참고 모드를 쓸 때는 지원하는 GPU 수와 워크플로를 별도로 확인합니다. 기본 실행 예제에는 다른 GPU 작업을 종료하는 --force를 넣지 않습니다.

05준비 확인·로그 읽기설치 성공·서버 준비·생성 성공은 각각 확인
# 터미널 B · 같은 코드 폴더에서
source scripts/cluster_env.sh
bash scripts/status.sh
h3video doctor
curl --fail http://127.0.0.1:30010/health

# Ref2VA를 함께 시작했을 때만
curl --fail http://127.0.0.1:30011/health

기본 포트는 FL2VA 30010, Ref2VA 30011입니다. 설정에서 바꿨으면 그 값을 사용하세요. status.sh에서 준비됨·로딩 중·꺼짐과 GPU 메모리를 구분하고, doctor에서 주소·폴더·FFmpeg 상태를 확인합니다.

# 현재 셸이 사용하는 저장·모델·엔진 경로
printf '%s
' "$H3_ENGINE" "$H3_MODEL_DIR" "$H3_DIFFUSERS_DIR" "$H3_LOG_DIR"

# 서버·설치 로그 파일 목록
ls -lt "$H3_LOG_DIR"

# 전체 진단: 생성 서버를 새로 시작하는 명령이 아닙니다.
bash scripts/diagnose.sh

가상환경의 import 성공, health 응답, 실제 테스트 영상 생성은 다른 검증입니다. 이 문서 작성 과정에서는 H100 서버를 새로 띄우거나 GPU 추론을 실행하지 않았습니다. 속도·품질은 직접 생성한 결과와 로그로 확인해야 합니다.

06CLI 사용 · 글·그림·참고 영상 생성요청 미리보기부터 첫 결과 확인까지
source scripts/cluster_env.sh

# 요청·장면 나누기만 확인 — 영상을 생성하지 않습니다.
h3video gen "자연광 아래 도자기 컵, 느린 카메라 전진" -s 8 --dry-run

# 준비된 서버에 실제 생성 요청
h3video gen "자연광 아래 도자기 컵, 느린 카메라 전진" -s 8

# 첫 프레임 / 첫·끝 프레임
h3video gen prompt.txt --first start.png -s 8
h3video gen prompt.txt --first start.png --last end.png -s 8

# 입력 파일 검사 · 서버·GPU 작업 없음
h3video inspect "inputs/인물 사진.png" inputs/motion.mp4
h3video inspect inputs/motion.mp4 --json

# 파일마다 -i를 반복하면 참고 종류 자동 판별
h3video gen "1번 사진 인물, 1번 영상의 동작" \
  -i "inputs/인물 사진.png" -i inputs/motion.mp4 -s 8

# 생성·복사 없이 JSON 계획만 확인
h3video gen "1번 영상의 동작" -i inputs/motion.mp4 --dry-run --json

# Ref2VA 서버가 준비되어 있을 때만
h3video gen "1번 사진 인물, 1번 영상의 걷는 동작"   --image person.png --video motion.mp4 -s 8

# 세로·시드·저장 위치
h3video gen prompt.txt -s 8 -r 9:16 --seed 42 -o ./exports/

--input 또는 -i는 파일 종류를 자동 판별하는 참고 입력입니다. 첫 화면을 고정하려면 --first를 사용하세요. H100에서 실행하면 그 서버나 공유 폴더의 파일 경로가 필요합니다. PC 경로가 자동 업로드되지는 않습니다. 웹에서는 파일을 클릭해서 고르거나 끌어 넣으세요.

inspect는 FFprobe가 있으면 해상도·길이를 확인합니다. 원격 주소와 FFprobe가 없는 환경의 메타데이터는 미확인으로 표시합니다. --dry-run --json은 생성·복사 없이 한 개의 JSON 계획을 출력합니다.

--first/--last는 실제 첫·끝 프레임, --image/--video/--audio는 참고 입력입니다. 두 종류를 혼합하지 않습니다. 참고 자료의 번호는 넣은 순서이며, 어떤 특징을 가져올지 명시하세요. 소리만 단독 참고 입력으로 쓰지 않습니다. 생성 결과는 출력된 결과 파일: 경로에서 확인합니다.

프롬프트는 문자열·텍스트 파일·표준입력으로 전달할 수 있습니다. --open은 기본 플레이어를 여는 옵션이므로 서버·헤드리스 작업에는 넣지 않아도 됩니다.

07웹 UI 사용 · H3 제작실 연결웹 서버와 GPU 생성 서버를 구분

CLI만 사용하면 웹 서버는 필요 없습니다. 웹 UI가 필요할 때만 별도 터미널에서 실행합니다. 아래 명령은 운영자가 사용할 설명이며, 현재 서비스를 자동으로 재시작하지 않습니다.

# 터미널 C · 웹 UI만 시작
cd /user-volume/minimax-h3-video
bash scripts/web.sh --cors https://77model.pages.dev

로컬 브라우저와 노드가 다르면 이미 승인된 보안 연결을 사용합니다. SSH 터널이 필요한 환경에서는 운영자가 다음처럼 루프백에만 연결할 수 있습니다. 방화벽 전체 개방이나 0.0.0.0 공개 바인딩은 이 절차에 필요하지 않습니다.

# 브라우저가 있는 PC에서 — USER@HOST를 실제 서버로 교체
ssh -N -L 127.0.0.1:8790:127.0.0.1:8790 USER@HOST

브라우저에서 http://127.0.0.1:8790을 엽니다. 77의 동영상 만들기에서 사용할 때는 상단 서버 주소에 이 주소를 넣고 연결합니다. 브라우저가 로컬 네트워크 접근 허용을 요구할 수 있습니다. CORS는 방문한 정확한 출처만 허용하고 *로 바꾸지 마세요.

화면의 글로 만들기·그림으로 시작·참고 자료로·JSON 한번에 중 하나를 선택합니다. 필요한 파일을 넣고 장면 수·길이·시드를 확인한 뒤 생성합니다. 오른쪽 결과 카드에서 재생·저장·명령어로 보기를 사용합니다. 웹 서버를 켜는 것만으로 GPU 모델이 준비되지는 않습니다.

03텍스트로 영상 생성한 명령에서 제출·대기·저장

mmx video generate \
  --model MiniMax-H3 \
  --prompt "A ceramic cup on a wooden table in soft morning light. Slow dolly in. Steam rises gently. Preserve the cup shape. Quiet room ambience. No text overlays." \
  --duration 8 \
  --ratio 16:9 \
  --download ./cup-01.mp4 \

  --timeout 1800 \

--duration은 4~15의 정수 초입니다. 세로는 --ratio 9:16, 정사각형은 1:1로 바꿉니다. 위 명령은 결과를 기다리고 내려받으므로 --async를 더하지 않습니다. 대기가 끊겨도 이미 생성된 작업이 있을 수 있으니 ID를 먼저 확인하세요.

04첫 프레임·끝 프레임으로 생성이미지의 시작·도착 상태 지정

--image는 첫 프레임입니다. 끝 상태를 정하려면 --last-frame을 더합니다. 시작 이미지 하나만 사용할 때는 마지막 프레임 옵션을 빼세요. 두 이미지 사이에 실제로 가능한 동작을 적습니다.

mmx video generate \
  --model MiniMax-H3 \
  --prompt "The person slowly turns toward the window from the starting pose to the ending pose. Preserve identity, clothing and room layout. One continuous shot." \
  --image ./start.png \
  --last-frame ./end.png \
  --duration 8 \
  --download ./turn-01.mp4 \
  --poll-interval 10 --timeout 1800 --non-interactive

첫·끝 프레임 모드와 다음 항목의 --reference-* 모드는 함께 쓰지 않습니다. 이미지를 참고해 인물·스타일을 유지하고 싶지만 첫 화면 자체를 고정할 필요가 없다면 참고 이미지 모드를 선택하세요.

05참고 영상·이미지·소리로 새 영상 만들기인물·동작·분위기·리듬을 나누어 지정

파일 하나마다 옵션을 반복합니다. 입력 순서대로 어떤 특징을 가져올지 프롬프트에 적으세요. 원본 영상의 특정 영역만 그대로 교체하는 편집을 보장하는 명령은 아닙니다.

mmx video generate \
  --model MiniMax-H3 \
  --prompt "Use reference image 1 for the character and clothing. Follow the slow walking motion of reference video 1, with a new rainy evening background. Keep identity consistent. Match the pace of reference audio 1. No subtitles." \
  --reference-image ./character.png \
  --reference-video ./walk.mp4 \
  --reference-audio ./rhythm.wav \
  --duration 10 --ratio 16:9 \
  --download ./walk-remix-01.mp4 \
  --poll-interval 10 --timeout 1800 --non-interactive

소리 참고에는 이미지 또는 영상 참고도 필요합니다. 영상의 움직임만 활용하려면 --reference-audio를 빼고, 프롬프트에서도 해당 소리 지시를 제거하세요. 참고 파일을 먼저 재생해 길이와 내용을 확인합니다.

ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate \
  -show_entries format=duration -of json ./walk.mp4

출처: 참고 미디어·작업 흐름 ↗

09진행 확인·끊긴 작업 복구기존 작업 ID부터 조회

생성 시 출력된 작업 ID를 보관하세요. 터미널 대기·다운로드가 끊긴 것과 서버의 생성 실패는 다릅니다. 새 유료 작업을 제출하기 전에 기존 ID를 조회합니다.

mmx video task get \
  --task-id YOUR_TASK_ID \
  --model MiniMax-H3 \
  --output json

queued/running이면 기존 작업을 기다립니다. succeeded이면 응답의 결과 url을 사용해 내려받습니다. H3 V2 조회 결과를 구형 V1의 file_id 방식과 섞지 마세요. 실패·취소·만료 상태는 작업 ID와 오류를 함께 확인합니다.

curl --fail --location \
  --output ./recovered-01.mp4 \
  'PASTE_THE_RETURNED_RESULT_URL_HERE'

결과 주소가 만료되면 같은 작업을 다시 조회하세요. 다운로드가 실패했다고 영상을 다시 생성하지 않습니다. 고정된 완료 예정 시간이나 퍼센트가 제공되지 않는 경우에는 대기 시간만으로 실패를 판단하지 않습니다.
